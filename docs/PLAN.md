## Architecture decisions (ADRs in `docs/decisions/`)

| # | Decision | Why |
|---|---|---|
| 0001 | Cargo workspace + one Rust host core shared by macOS, Windows and Linux; OS code only in per-OS backend crates | One session/crypto/mapping implementation for all three hosts; OS-specific code is just the virtual-pad backend and packaging |
| 0002 | Desktop UI = Tauri v2 shell with a single static HTML/CSS/JS frontend (no bundler) | One companion UI for three OSes; native window; small binary |
| 0003 | Wire security = Noise `XX_25519_ChaChaPoly_SHA256` on TCP control + ChaCha20-Poly1305 UDP input with explicit 64-bit nonces and host-issued random keys | Standard, specified handshake; independent implementations cross-checked by test vectors and against `snow` |
| 0004 | Pairing = QR (host static key + 128-bit one-time token) or 6-digit numeric comparison with nonce commitment (Bluetooth SC style). No typed static PIN | A typed low-entropy PIN without a PAKE is offline-brute-forceable by an active MITM |
| 0005 | Android: `:app` + shared pure-Kotlin `:protocol` module (lives in `protocol/kotlin`), current stable AGP/Kotlin/Compose (skill pins are stale) | JVM-fast protocol tests; NowInAndroid layering inside `:app` |
| 0006 | iOS: SwiftUI app generated by XcodeGen, shared `NineKit` Swift package in `protocol/swift` | `swift test` can verify the protocol on macOS without full Xcode |
| 0007 | Windows backend: own **KMDF** VHF HID gamepad driver (VHF supports kernel-mode source drivers only) behind an IOCTL interface; ViGEmBus rejected (archived); libvirtualhid kept as documented alternative | Supportable, Microsoft-documented framework; no third-party licence dependency |
| 0008 | Linux backend: `/dev/uinput` evdev gamepad, udev rule for non-root access | Kernel-standard, no driver |
| 0009 | macOS backend: `IOHIDUserDevice` behind Apple's `com.apple.developer.hid.virtual.device` entitlement; reported as **blocked** until granted | Only supportable route; verified NULL without entitlement |
