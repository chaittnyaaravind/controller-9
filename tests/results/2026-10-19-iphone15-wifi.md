# iPhone 15 → Mac over Wi-Fi — first real-device run (2026-10-19)

Hardware: iPhone 15 (iPhone15,4), iOS 27.0.1, Controller-9 iOS app built from `ios-build` (`80d81c3`),
signed with a free Personal Team via Xcode 27.1 on the Mac, installed with `devicectl`. Host: the
MacBook's `controller9 host` (identity `b3290803d963ffe4`), real Wi-Fi (not loopback). Paired by QR.
Evidence: host `--stats-every 1` JSON (1 Hz snapshots of the received state), recorded from 21:45:54.

The Mac backend is still blocked (no `com.apple.developer.hid.virtual.device`), so this proves phone,
link and input path — **not** that a Mac game sees the controller.

## Automated touch accuracy on the device (Xbox-style layout)

XCUITest `ControllerAccuracyUITests` (apps/ios/UITests) presses every control through the real touch
pipeline on the iPhone 15; the oracle is the host's `--trace-input` log (millisecond timestamps).
Run 2 (nobody touching the phone): **20/20 PASS**.

| Step | Host received | Hold |
|---|---|---|
| A, B, X, Y, LB, RB, View, Menu, Guide, LS, RS (one at a time) | each exactly its own bit, nothing else | 593–602 ms for 600 ms presses |
| LT, RT | `lt` / `rt` 100 % only | 597–600 ms |
| D-pad left aimed high (14 %, 40 %), up, right, down (off-axis) | Left / Up / Right / Down only — no diagonal | 593–599 ms |
| Tap in the gap between the top and right face buttons | nothing | — |
| Left / right stick dragged right | `lx+` / `rx+` only | ~700 ms |

Bug found by the first run and fixed: the app's in-memory settings overwrote `lastHost` (written by the
connection manager) on the next settings change, so Play stopped auto-connecting after a relaunch.
